# Portfolio Cluster Map V1

Status: **OBSERVED CLUSTERING / HYPOTHESES ONLY**

Discovery treats the full accessible portfolio as the search space. At the 2026-09-21 cut, that is 58 repositories: 23 public and 35 private.

Because this repository is public, private repository names and private mechanism details are deliberately omitted. Their presence still affects counts, overlap analysis, and candidate generation.

The 2026-09-19 repository-role partition is not carried forward automatically after inventory drift. The refreshed public research cut is the current public-safe observation surface; cluster membership below remains non-exclusive and revisable.

## 1. Execution integrity

Public anchors: `project-runner`, `wip`, `driftguard`.

Questions:

- Is there one reusable mechanical core for exact work identity, CAS/fencing, leases, idempotency, effect reconciliation, verification, and crash recovery?
- Which parts are orchestration semantics versus generic integrity mechanics?
- Does a shared mechanism reduce total state-machine complexity, or merely move it into adapters?

Strong current hypothesis: narrow effect-integrity mechanics can be compared independently of each project's larger state machine. This remains an experiment, not a declaration.

## 2. Evidence, provenance, and custody

Public anchors: `roots`, `testament`, `on-theo`, `semanticatlas`.

Private participants include systems concerned with evidence storage, semantic provenance, historical retrieval, industrial evidence, and currentness.

Question: can custody, lineage, and provenance mechanics be shared while each domain retains its own standards for what evidence *means*?

The failure condition is a common record format silently becoming a common ontology or truth authority.

## 3. Coordination and transport

Public anchor: `vera-mesh`.

Private participants remain substantial and are intentionally unnamed here.

Question: can message envelopes, routing, delivery receipts, dead-letter handling, and device transport share a neutral protocol without making the transport layer an authority system?

A candidate abstraction must first prove itself in a real cross-project flow.

## 4. Cognitive-base overlap

Public anchors: `hc-brain`, `transcendence`, `god-brain`, `bt2`.

The prior portfolio audit observed substantial same-path byte identity between HC Brain and Transcendence on exact historical subjects. Discovery must remeasure current heads rather than carrying an old count as current truth.

The `bt2` public repository currently presents a Hyperconnectome-template README while installed Build Team Two Project instructions assign that repository a Build Team Two source role. Discovery records this as a role discrepancy requiring source-history investigation; it does not silently choose one interpretation.

The base/overlay experiment remains:

`pinned base + explicit overlay -> identical target tree`

If exact reconstruction fails, deduplication is not justified.

## 5. Experiment mechanics

Public anchors: `world-zero`, `mosaic`, with `god-brain` as a research consumer candidate rather than an established shared-harness consumer.

Potentially reusable mechanics include:

- preregistration;
- deterministic run manifests;
- exact subject hashes;
- seeded experiment configuration;
- negative controls;
- holdouts;
- immutable receipts;
- statistical summary plumbing.

Scientific hypotheses, evaluators, and validity criteria remain owned by their projects.

## 6. Semantic cognition and mediation

Public anchors: `spm`, `unvtrslr`, `semanticatlas`, `rezon`.

Observed questions include:

- whether semantics/pragmatics can be made first-class computational state;
- how communication can bootstrap without a shared language or ontology;
- how semantic concepts retain provenance and unresolved distinctions;
- which reasoning outputs can cross system boundaries without exporting epistemic authority.

These repositories are not presumed to share one ontology or one cognition stack merely because they all concern meaning.

## 7. Vera runtime and control

Public anchors: `driftguard`, `vera-mesh`, `vera-synology`.

Most members of this cluster remain private.

Discovery should look for shared *mechanics* while treating Vera identity, current self-state, consent, relationship semantics, and release authority as project-specific boundaries.

Transport and packaging are not evidence of identity continuity or runtime currentness.

## 8. Industrial diagnostic chain

Public anchor: `abil`.

Private participants may cover evidence acquisition, reconstruction, and service/deployment layers.

Working architectural question:

Can trustworthy machine evidence/replay feed brownfield reconstruction and bounded control without each layer rebuilding acquisition and provenance machinery?

No actuation or production authority follows from architectural reuse.

## 9. Review and validation

Public anchor: `voss`.

Question: can hostile review, forensic audit, exact-subject qualification, and review receipts share narrow mechanics without turning the reviewer into the authority that owns the reviewed project?

Reviewer output is evidence about a subject, not an automatic promotion or effect authorization.

## 10. Relationship and continuity systems

Public anchor: `Attune`.

Question: which persistence, memory, preference, boundary, and continuity mechanics are reusable beneath relationship-oriented AI without generalizing relationship identity or consent semantics into a portfolio-wide ontology?

This is an emerging family only. No reuse candidate is implied by one observed repository.

## 11. Domain negative controls

Public anchors: `on-theo`, `testament`, with `unvtrslr` useful as a semantic non-equivalence stressor.

A good shared substrate should work underneath specialized domains without flattening their evidence classes, canon rules, scientific questions, privacy models, authorship, or explicit non-equivalence.

Negative controls are first-class Discovery evidence. A project that **should not** fit an abstraction can be more informative than a project that does.
