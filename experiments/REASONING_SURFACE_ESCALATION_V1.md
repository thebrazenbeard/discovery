# REASONING_SURFACE_ESCALATION_V1

Status: HYPOTHESIS / MULTI-CONSUMER CANDIDATE / NOT PROMOTED

Date: 2026-10-07

## Candidate

A controlled same-task experiment across:

- Desktop Chat GPT-5.6 Sol High reasoning;
- ChatGPT Desktop Work Ultra reasoning;
- Firefox cloud Work Max reasoning;

produced evidence that higher-cost Work surfaces can be useful as specialist reasoning workers while remaining separate from the coordinator that invoked the work.

The candidate reusable mechanism is **not** "copy the Work connection pattern." It is an exact-bound reasoning escalation contract.

## Observed evidence

On WorkLaptop, using a common companion tracer:

- High controlled window: 0 MXC launches, 2 new established Codex TLS connections;
- Desktop Work Ultra controlled window: 59 MXC launches, 73 new established Codex TLS connections.

Ultra and Max independently converged on central P.O.R.T.A.L. execution-control failures. Max's server-side worker topology remained unobservable from local Firefox telemetry.

Evidence ceiling:

- socket/process fanout is diagnostic evidence only;
- process/socket count does not establish agent count;
- transport pattern does not grant or prove reasoning tier;
- no hidden chain-of-thought or cloud worker topology was recovered.

## Candidate reusable contract

```text
coordinator
  -> bounded reasoning requirement
  -> exact subject/context binding
  -> supported callable specialist surface
  -> structured result artifact
  -> verification
  -> coordinator integration
```

The contract should preserve:

- literal task;
- exact source version;
- context manifest;
- worker/surface observation;
- independence metadata;
- resource budget;
- authority ceiling;
- attempt identity;
- ambiguity/retry state;
- returned artifacts and verification receipts.

## Consumers

### Rezon

Primary semantic owner for reasoning operator classification, specialist eligibility, independence, evaluation, and escalation semantics.

Current action: populate Rezon with the empirical surface study and escalation-bridge design.

### Vera

Potential consumer for delegating difficult hostile review, proof checking, or synthesis while preserving Vera identity, authority, current correction, and final integration.

Current action: source-only routing evidence; no active specialist route.

### P.O.R.T.A.L.

Potential execution substrate for exact-bound dispatch, resource admission, attempt ownership, STOP/HOLD currentness, and reconciliation.

Current action: design-only. Implementation is blocked on the execution-control failures reproduced by the stress test.

### Tattler

Observation/qualification support for local process and transport evidence.

Current action: preserve the case study and claim ceiling; Tattler must not become a model detector.

## Negative consumers / non-owners

### Executor / WorkBridge / WorkBridgeMCP

These are workstation execution/transport substrates. They should remain model-agnostic and should not acquire reasoning-tier semantics merely because they can execute tools on a host.

### CCB Base / Chat Communication Bus

The Bus may eventually transport escalation envelopes as data, but it should not own reasoning-tier eligibility or duplicate Rezon routing semantics.

### BT2 / Masamune

These projects may consume resulting specialist artifacts or independent-review metadata, but duplicating the escalation architecture into them now would create competing semantic ownership.

## Reuse test

Discovery's promotion rule requires at least two materially independent consumers and measured simplification.

This candidate has multiple plausible consumers, but promotion is premature because:

1. Rezon's bridge is not yet executable;
2. P.O.R.T.A.L. has unresolved attempt/STOP/HOLD defects that would make expensive delegation unsafe;
3. no supported programmatic Ultra/Max adapter has been qualified;
4. Work Max cloud topology is outside local-observation reach;
5. independence semantics still require explicit contamination metadata.

## Next evidence needed

To move from HYPOTHESIS toward EXPERIMENTING / PROVEN_REUSABLE:

- deterministic/mock escalation adapter in Rezon;
- hostile tests for stale context, STOP/HOLD, replay, changed capability requirements, ambiguous completion, and false independence;
- P.O.R.T.A.L. repair and exact-head regression of its control boundaries;
- one supported callable specialist surface;
- one second independent consumer that uses the same contract without Rezon-specific assumptions;
- measured comparison showing the shared contract removes more complexity than per-consumer bespoke dispatch.

## Disposition

Keep the semantic contract centered in Rezon.

Permit Vera and P.O.R.T.A.L. to consume it through explicit versioned bindings.

Keep Tattler, Executor, WorkBridge, and CCB provider/transport neutral.

Do not promote socket/process signatures into routing authority.
